# PQ-ID: issuance-bound digital credentials

Code and experimental evidence for **Auditing and Redesigning a Zero-Knowledge Digital Identity System: Issuance-Bound Credentials with Post-Quantum-Signed Statements**, by **Kushal Sachdeva**.

The repository contains the v4 credential protocol, its v2/v3 comparison implementations, Circom circuits, EVM registries, security tests, measurement harnesses, and the supplementary experiments used in the IRIS paper. The main implementation uses ML-DSA-44 for signed statements, ML-KEM-768 for wallet sessions, Poseidon Merkle trees for issuance and revocation, and Groth16 over BN254 for selective disclosure.

## Start here

For validation on Linux using the pinned environment:

```bash
docker build -f artifact/Dockerfile -t pqid-publication .
docker run --rm pqid-publication bash artifact/rebuild.sh --full --no-install
```

For an installed environment, use Node 24.18.0, Circom 2.2.3, Anvil 1.5.1, Python 3.11+, and Bash:

```bash
python -m venv .venv
# Linux/macOS: .venv/bin/python; Windows: .venv/Scripts/python.exe
.venv/bin/python -m pip install -r artifact/requirements.txt
export PQID_PYTHON="$PWD/.venv/bin/python"
bash artifact/rebuild.sh
```

On Windows with Git Bash, select the Windows interpreter when creating the environment:

```bash
.venv/Scripts/python.exe -m pip install -r artifact/requirements.txt
export PQID_PYTHON="$PWD/.venv/Scripts/python.exe"
bash artifact/rebuild.sh
```

The default command installs the locked Node dependencies, verifies the committed setup pins and publication manifest, typechecks the code, runs the v4 tests, and runs the portable v2/v3 circuit suites. Some tests start local Anvil instances or compile test circuits. `--full` additionally checks the pinned environment, recompiles v4 into scratch output, audits its development key, and compares a fresh security-suite run with the stored verdicts. Outputs go to `artifact/out/`; timed measurement campaigns are separate commands.

See [REPRODUCE.md](REPRODUCE.md) for dependencies, individual checks, supplementary runs, and the limits of reproduction.

## Evidence and interpretation

Recorded results retain their experiment labels and environments. `[M]` means measured, `[S]` means simulated or estimated, `[A]` means an assumption, and `[F]` means future work. A rejected finite test catalogue does not establish a security probability or a formal proof of the complete protocol.

The committed v4 Groth16 artifacts are labelled **development key**. Their secret setup contribution was discarded, so the key is audited against the pinned circuit and transcript rather than regenerated byte-for-byte. The ceremony kit does not imply that an independent production ceremony has completed. Groth16/BN254 and the EVM account layer are classical cryptography; post-quantum signatures and session encryption do not make the entire system post-quantum secure.

Historical source hashes in result records refer to the original experiment snapshot. Publication comment and metadata normalization can produce different source hashes; the recorded measurements and setup artifacts are unchanged. `MANIFEST.sha256.tsv` identifies the files in this publication package. Exact historical source-hash checks and new experiment runs are separate forms of validation.

The phone and zkVM directories include integration and exploratory work. Their presence does not establish a completed physical-device experiment or an independently verified deployment. Consult each protocol and result status before using a number.
